# xinle.xyj.link

特权门票每日价格采集与渠道比价看板，支持旅游地区筛选、1日/1.5日成人与儿童分类、本地票种设置和 Electron 桌面版。

## 从源码运行

安装 Node.js 24 和 pnpm 后，在项目目录执行：

```powershell
pnpm install --frozen-lockfile
npm start
```

打开 <http://127.0.0.1:3186>，在「登录配置」中保存自己的账号密码，再点击「手动刷新价格」。开发模式默认使用本机 Edge；也可通过 `XINLE_BROWSER_PATH` 指定 Chromium 可执行文件。

仓库仅包含源码、构建脚本和测试源码，不包含 EXE、已安装依赖、账号密码、抓取数据或测试日志。构建桌面版之前，先准备 Electron 和采集浏览器：

```powershell
node node_modules/electron/install.js
pnpm exec patchright install chromium
npm run build:exe
```

## Windows EXE

Windows 10 / 11 64 位可直接运行 `dist/XinlePriceDashboard-Electron.exe`，内置 Electron 桌面窗口、Node 和采集用 Chromium。界面不显示 Chrome 测试版提示，价格采集全程无头运行，不弹出浏览器。首次打开后填写「登录配置」，再手动刷新。发行包不含开发电脑账号密码，数据保存在当前用户的 `%LOCALAPPDATA%\XinlePriceDashboard\data`，与旧版 EXE 共用数据目录。

构建命令：`npm run build:exe`。详细说明见 [Windows 发行版说明](packaging/WINDOWS-EXE.md)。

## 本地价格看板

运行 `npm start` 后打开 <http://127.0.0.1:3186>。

页面可按旅游地区、月份、日期和票种筛选。地区使用与票种一致的按钮切换样式，打开页面默认选择“北京环球度假区”。地区来自实际采集的景区列表，支持多个景区、全部分页；选择“全部地区”时也会按景区独立展示，避免不同景区的价格混排。每个日期分为“1日成人、1日儿童、1.5日成人、1.5日儿童”，每个商品 ID 作为一个渠道，按日历价格从低到高排序。同价渠道并列排名，完整保留产品名称和提前预订天数。

无法确认游玩时长或适用人群、名称与接口人群冲突、多人票及其他特殊票种保留在“待设置”，不会强行纳入四种单人票排名。可直接从该渠道进入票种设置；价格数据仍完整采集和导出。

比价区提供“列表方式 / 日期方式”切换，默认使用原列表。日期方式按月展示四种票种的日历，每格显示当前地区、同一票种当天的最低可预订报价；选择“全部地区”时各地区仍使用独立日历。仅 `valid=1`、已纳入价格表且库存不为0的记录参与最低价计算，没有可用报价时显示“暂无”，真实0元报价保留为 `¥0.00`。可通过月份筛选或日历左右按钮切换已返回数据的月份，点击有报价的日期展开当天渠道详情，清除日期后继续浏览整月。保存本地票种或手动刷新后，两种视图会同步更新。

刷新按钮左侧的“登录配置”可编辑账号和密码。保存后，后续登录与价格采集优先使用该配置，不需要重启服务；正在执行的采集继续使用启动时的账号。已有密码时留空可保留原密码，密码不会回显到页面。

“票种设置”列出已采集的全部渠道，可通过地区按钮筛选，并按名称、编号或地区搜索，逐个选择四种票种之一或“跟随接口”。打开弹窗时跟随看板当前地区，从某个渠道快捷进入时自动切到该渠道所属地区；切换地区保留未保存的修改，可一次保存多个地区的设置。本地票种按商品 ID 保存，立即应用于比价、统计和导出 JSON，后续采集及程序重启仍优先使用；渠道暂时下架不会删除其设置。恢复“跟随接口”后结合原始接口人群和产品名称中的游玩时长自动分类。旧版本地成人/儿童设置兼容为1日成人/1日儿童，可按需要改成1.5日。刷新过程中也能保存设置，刷新完成时会按最新本地设置发布完整结果。

同一个渠道 ID 只要存在本地设置，就不会被再次拉取的接口票种或产品名称覆盖；列表、日历、JSON 和 Excel 均采用该设置，只有主动选择“跟随接口”才取消本地覆盖。

点击“手动刷新”后，服务会在后台无头运行登录和采集流程，显示进度。完成全部渠道采集后，原子替换 `output/ticket-prices.json`，同时更新其他导出文件，页面自动显示最新数据。刷新期间可继续浏览旧数据；刷新失败会保留上一次成功的数据。重复点击或多个页面同时刷新只启动一次采集。

服务只监听本机，账号配置不会发送到页面。`PORT` 环境变量可更改端口。停止运行终端即可停止服务，已保存的 JSON 仍可在下次启动时加载。

## 命令行采集

在项目目录运行：

```powershell
npm run prices
```

脚本优先使用页面保存的登录配置，没有保存过时兼容 `.env.local` 中的账号。使用项目已配置的 Edge（`--no-proxy-server`），登录后重新访问首页，再打开“门票预订 → 我的特权产品”。它会读取所有产品列表分页，逐个查询预订日历使用的价格接口。仅查询价格，不提交订单。

默认采集不显示浏览器，完成后自动退出；调试时运行 `npm run prices -- --visible`，需要保留窗口时运行 `npm run prices -- --visible --keep-open`。单独登录仍使用 `npm run login`。

## 导出文件

页面顶部“导出 Excel”下载标准 `.xlsx` 工作簿，导出全部已保存地区、渠道和日期，不受页面当前筛选限制，也不会重新请求票务网站。工作簿包含：

- **渠道每日最低价**：每个渠道一行，每个日期一列，保留地区、票种、渠道 ID、完整名称和票种来源。冻结表头与渠道信息，金额为可计算的数字。
- **每日票种最低价**：同一地区、同一票种、同一天的最低报价，列出所有并列最低渠道及完整名称。
- **报价明细**：全部采集价格及有效性、库存状态，便于核对未参与最低价计算的记录。
- **导出说明**：数据更新时间、导出范围和计算规则。

Excel 最低价与日历规则一致：只比较有效且库存不为0的记录；同渠道同日有多条可用记录时取最低值。无可用价格的格子留空，真实0元报价保留数字0。“待设置”渠道保留在渠道总表与明细中，不纳入跨渠道的票种最低价汇总。导出时重新读取本地票种配置，人工设置始终优先。

- `output/prices-by-date.json`：`adult_1d / children_1d / adult_1_5d / children_1_5d / other → 商品ID → YYYY-MM-DD → 价格`。
- `output/prices-by-month.json`：同样五个分组，结构为 `票种 → 商品ID → YYYY-MM → 日号 → 价格`，适合按用户示例读取某个月的数据。
- `output/ticket-prices.json`：完整结果（`schemaVersion: 2`），含商品名称、旅游地区、游玩天数、原始票种、每日价格明细、库存/有效性、统计、警告及采集状态。地区字段为 `destinationKey / destinationName`，另保留 `spotId / spotName`。
- `output/ticket-prices.csv`：供 Excel 查看的一日一行明细。

所有金额单位为元。简表使用预订日历前端实际显示的 `mall_price`；完整明细也保留 `b2b_price`（平台价）和 `market_price`（门市价）。不会用列表上的起始价替代每日价格。

价格请求为 `POST /scm/goods/getGoodsPrice`，参数是 `goods_id`、空的 `product_scan_goods_id` 和 `scanCode`。请求不限定月份，保留接口当次返回的全部日期；未返回的日期不会填零或根据邻日推算。

`prices` 和 `dayNumbers` 只收录 `valid=1` 的日期，全部状态均保留在 `rows`。库存为 `-1` 不会被删除；库存为 `0` 会保留记录并给出警告，价格记录不等于保证仍有库存。

票种优先按 `config/ticket-types.json` 中的本地设置分类，未设置时结合接口 `ticket_type` 和名称中的明确游玩时长自动识别。“提前15天”“提前1天”“2日内预定”属于预订限制，不作为游玩时长。接口原人群保留为 `sourceTicketType`，自动分类为 `sourceGroup`，有效人群/分类使用 `ticketType / group`，`visitDays` 为 `1`、`1.5` 或 `null`，`ticketTypeSource` 标记 `local` 或 `remote`。

例如商品 1036 的接口类型为 `CHILDREN`，名称包含“成人票”，会归入 `other`（待设置）并在 `classificationReason / warnings` 提示原因；人工确认后可设置为四类之一。旧快照读取时会转换为新分类，保留原日期与金额，再次刷新或保存票种后持久化新格式。

每次成功采集使用临时文件与重命名替换同名导出文件，主 JSON 最后发布；旧主文件备份为 `output/ticket-prices.previous.json`。部分接口失败或数据校验失败时返回非零退出码，保留上一次成功的数据，不发布不完整结果。

页面保存的账号配置持久化在本机 `config/login.json`，已被 Git 忽略且不作为静态文件提供给浏览器。`.env.local` 中的 `XINLE_USERNAME` 和 `XINLE_PASSWORD` 作为未保存网页配置时的兼容来源。配置接口只返回账号和是否已设置密码，日志不输出凭据。
